# memory-redteam —— 自研长期记忆子系统（写 / 读 / 遗忘 + 跨会话持久化 + 投毒红队）

一套**可跑的**跨会话记忆实现与回归，零依赖（node 原生 ESM，不需要 `npm install`）。
它把 `notes/long-term-memory.md` 里**已成文的判定**变成可执行代码与断言，并且**不依赖 pi 的 Magic Context**——
被问"你自研过长期记忆吗"，`npm run demo` 就是答案，`node test.mjs --ablate` 是它"有牙"的证明。

对齐的笔记章节（代码里以 `[Sx]` 标注，笔记 §S7 回归框给出反向映射表）：

| 代码 | 对齐 | 内容 |
|---|---|---|
| `src/memory.mjs` | §S3/§S4/§S5/§S7/§S10 | 写路径决策树、读路径注入、冲突消解状态机、四道投毒防线、遗忘与血缘传播 |
| `src/retrieval.mjs` | §S4 | 混合检索：BM25（k1=1.2, b=0.75，罕见词高 IDF）∥ hash embedding → RRF 融合（k=60） |
| `src/persist.mjs` | §S2/§S3 | 事件日志（JSONL）落盘 + 顺序重放重建；审计与条目快照 |
| `src/persist-check.mjs` | §S10 步骤 7 | 持久化断言子进程入口（`--write` / `--verify`）——新进程重建可比 |
| `src/scenario.mjs` | §S10 步骤 1-7 | 固定端到端场景（写入 → 召回 → 冲突 → 评测 → 遗忘）——演示/探针/持久化共用同一份 |
| `src/redteam.mjs` | §S6/§S7 | 16 条探针：单元级 R1-R11 + 端到端 E1-E5（每条声明消融防线） |
| `src/demo.mjs` | §S10 | `npm run demo`：可读的完整走查 |

## 跑法

```bash
cd memory-redteam
npm run demo               # 端到端走查：写入 → 召回 → 冲突消解 → 遗忘传播 → 跨会话持久化（可读叙述）
node test.mjs              # 正跑：16/16 条探针守住 → 退出码 0
node test.mjs --ablate      # 消融自检：逐层关掉防线，探针必须失败 → 退出码 0（18/18 层承重）
node test.mjs --persist     # 追加跨会话持久化断言（两个子进程 + 本进程三方 digest 比对）
node test.mjs --only R3     # 只跑一条
npm test                   # 等价于 node test.mjs
npx tsx src/index.ts       # 等价入口（转发到 test.mjs，输出逐字节一致）
```

要求 node ≥ 18（原生 ESM，无第三方依赖，无构建步骤；`src/index.ts` 是纯 JS 语法的转发入口，`tsx` 非必需）。

当前状态（2026-10-12 实测）：

```
16/16 条探针守住（正跑，退出码 0）
15/15 条探针对其防线敏感（消融自检逐层验证 18/18 层，退出码 0）
持久化断言 4/4 通过（新进程用同一 JSONL 重建 ≡ 写入进程 ≡ 本进程独立跑一遍）
```

**确定性**：时钟由调用方注入，缺省固定为 `FIXED_NOW`（§S10 走查基准时间）；代码里**没有 `new Date()`/`Date.now()`**
（`grep` 可自查：只有注释提到它们）。同一命令连续两次运行输出逐字节一致（`diff` 为空）——回归报告与演示都不含墙钟时间戳、不含临时路径与 pid。

## 它现在是什么（能力清单，逐条可查）

**写路径**（`src/memory.mjs` `write()`，走 §S3 决策树）
1. **信任分级**（§S7 防御1）：`user_confirmed > inferred > untrusted`；低信任候选可落库但不得自动注入、不得覆盖高信任事实
2. **注入扫描**（§S7 防御2）：4 类签名族（外链脚本 / 执行脚本 / 凭据字面量 / 指令覆盖），低信任命中即拒
3. **高危独立审批**（§S7 防御3）：`PROCEDURE`/`CREDENTIALS`/`EGRESS` 未审批挂起、不进注入集
4. **审计留痕**（§S7 防御4）：write / supersede / coexist / expire / delete / advisory 六类 op，带 `triggered_by` 轨迹
5. **冲突消解**（§S5）：同 scope+category 的四种处置——覆盖（不物理删除）/ 并存（带时间戳）/ 时效到期 / 拒绝（低信任或更旧）
6. **时效窗口**（§S5）：`ttl` → `valid_to`，`active → expired` 状态迁移（归档不是删除）
7. **遗忘传播**（§S10 步骤 7）：硬删内容 + 清空向量 + 墓碑 + 沿 `derived_from` 血缘传播（派生物置 `redacted`，保留 id 与血缘）

**读路径**（`injectable()` / `recall()` / `injectionAudit()`）
- **scope 过滤**先于打分（§S4：在检索时做，不是生成后做）
- **混合检索**：BM25 词法路 ∥ 字符三元组 hash 向量路 → **RRF 融合**（k=60，用排名做公共货币），每条结果带**双路排名归因**（§S6 错误归因签名：一路漏=单路盲区）
- **注入集只接受"达阈值 + 过防线"的条目**：`active` + 信任闸 + `confidence ≥ 0.8` + 时效窗口内；`injectionAudit()` 对每条给出**进/不进的逐条理由**

**跨会话持久化**（`src/persist.mjs` + `src/persist-check.mjs`）
- 每次变更（条目快照 + 审计记录）作为事件追加进 JSONL；重建 = 顺序重放（同 id 后写覆盖前写，保序）
- `node test.mjs --persist` 起**两个独立子进程**：一个写、一个新进程用同一 JSONL 重建，再与本进程独立跑一遍比对——
  三方 digest（含注入集/一致性/污染率/墓碑/召回结果）逐字节一致才算通过

## 消融自检：为什么逐层，以及它抓到的真缺陷

一个永远通过的测试是零信息量的。`--ablate` 会关掉该探针声称守住的防线再跑一遍——关掉后**必须失败**，
否则这条探针没在测那道防线（恒真断言）。

**多防线探针必须逐层关**：一条探针同时宣称测三道防线时，"三道一起关掉探针就失败"什么都证明不了——
可能只有一道在起作用、另外两道是摆设。runner 对多防线探针**每次只关一道**，每道都必须承重。

本仓库用这个更严的口径实测抓到并修掉了这些真缺陷（都可复现）：

1. **原 R5 探针测的其实是"删除判定"**：它在同一次运行里既写又 `forget()`，关掉 `auditTrail` 时"写留痕"和"删留痕"同时消失，
   探针测不出是哪一层。→ 重写为五类 op 各有独立证据。
2. **原 R9 的断言与防线耦合**：它用 `store.audit` 里的删除记录当"传播发生了"的证据，于是关掉 `auditTrail` 也能让探针失败
   （敏感度来自无关防线）。→ 改为只断言 `forget()` 返回的传播结果与派生物字段。
3. **原 R7 宣称的 `ttlWindow` 从未被触发**：它的"过期条"用了 `other-repo` scope，真正挡住它的是 `scopeFilter`；
   逐层消融下 `ttlWindow` 那层是摆设。→ 改成同 scope 过期条，并把"关掉某层该看到哪一条泄漏"写进断言细节。
4. **污染率口径把签名当成了证据**：原口径"内容命中注入扫描签名即算污染"，会把**用户自己给的、已审批的运维步骤**
   （"部署前先运行 preflight.sh"命中 `script-exec`）虚报成污染（实测污染率从 0 变成 33%）。
   → 口径改为按**来源与状态**判定（untrusted / 矛盾态 / 时效到期），签名交叉单列 `advisories`，
   写路径对"用户来源命中签名"的条目**放行 + 审计留痕**（签名是线索不是证据，但不隐藏）。
5. **非确定性的 `new Date()`**：原 `write()` 在缺省路径里取墙钟，墓碑时间戳会漂移、回归无法逐字节复现。
   → 时钟由调用方注入、缺省固定。
6. **遗忘后派生物仍可能被注入**：原 `forget()` 只清空派生条目的 `content`，`status` 仍是 `active`——
   清空内容但状态没变，注入集判定仍可能放行（且不再有内容可读）。→ 派生物置 `redacted`。
7. **"混合检索"名不副实**：原 `recall()` 只有 BM25 单路，笔记 §S4 明确"记忆里专有名词/ID 多，BM25 这一路不可省"
   但另一半（向量路 + RRF）并没实现。→ 补 `retrieval.mjs`：双路 + RRF + 逐条路径归因。

## 它不是/不宣称什么（边界）

- **不是生产记忆系统**：单进程单写者、无文件锁、无 `fsync`（崩溃可能丢最后若干条）；元数据是 JSONL，不是数据库。
  崩溃恢复的完整版在 `durable-execution-demo/`（journal + 幂等 + 未知态处置）。
- **embedding 不是语义嵌入**：64 维字符三元组 hash（确定性、可打印、可复现），没有 ANN 索引、没有 cross-encoder rerank。
  `rag-demo` 用 k1=1.5/b=0.75 + 768 维 FNV-1a；本套件参数与实现**独立**（不 import rag-demo，避免一份算错被另一份掩盖），
  因此**不以"复用了 rag-demo"自居**——同源的是机制与 tokenizer 约定，不是代码。
- **注入扫描是文本模式层**（4 类签名族），拦不住语义伪装——这正是 §S7 需要"多源印证/人审"的原因。
- **命中计数不落持久化日志**：`hit_count`/`last_hit_at` 是读路径回写的信号，本轮不在事件日志里，
  跨进程等价性断言已显式排除这两个字段（见 `persist.mjs` 顶部边界声明）。
- **不断言 §S10 的示例数值**（`recall@1 = 0.87` 等）：笔记原文已声明那是走查示例、不是既成事实；
  R11 只断言其中的机制（罕见词高 IDF 排序）。
- **不替代笔记**：判定与理由的权威表述仍在 `notes/long-term-memory.md`；本套件只把其中**可判定的部分**变成代码与回归。
