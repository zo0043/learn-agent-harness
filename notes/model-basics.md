## S1 推理管线：一次生成的两个阶段

```
prefill（吃 prompt）→ decode（逐 token 吐）
  计算受限                内存带宽受限（每步只生成 1 token，
  （大矩阵乘，GPU 算力打满）  但要把整个 KV cache 搬一遍）
```

**KV cache（必问，要能推导）**：
- Transformer 自回归生成时，前面所有 token 的 K/V 矩阵可以缓存复用，不必每步重算 → 内存占用 ≈ `2 × layers × kv_heads × head_dim × seq_len × bytes`（2=key+value）
- **两个直接推论（面试推导题）**：
  1. 上下文越长 → 每步 decode 越慢、显存越多（为什么 1M 窗口又贵又慢；为什么长会话要压缩——A⑧ 的模型侧理由）
  2. 同模型并发多请求 → KV cache 总量受限 → 吞吐瓶颈在**显存不在算力**（为什么推理服务按显存规划容量，J 课延迟/成本的底层原因）
- 相关优化（意识级）：GQA/MQA（减少 KV head 数）、PagedAttention（vLLM：KV 分页管理，减少碎片）、量化（FP8/INT8，省带宽）

## S2 解码与采样：参数如何改变 agent 行为

| 参数 | 作用 | agent 场景设定 |
|---|---|---|
| temperature | 软 softmax：高=分布平=更随机 | **结构化输出/工具调用=低温**（0 附近）：参数拼错=整步失败；开放生成（摘要/文案）可适度高 |
| top-p / top-k | 截断候选集 | 与 temperature 二选一主用即可 |
| seed | 可复现（支持的 provider） | **评测/回放必用**（E 课 S6、D 课 S5：同 seed 同温度才能 diff） |

**面试点**："温度不是质量旋钮，是**分布平度旋钮**——任务要确定性（代码/参数/JSON）就压低，要多样性（头脑风暴/自我采样 self-consistency）才抬高。"
self-consistency（C 课 S3 的 parallelization）= 高温多采样+多数表决，用成本换稳定性（FinHot 双模型评分=跨模型版的自洽）。

## S3 上下文窗口 vs 有效上下文

- **窗口**（hard limit，128K/1M…）≠ **有效长度**（注意力质量随长度衰减，"context rot"/lost-in-the-middle——harness 课第五节已建立）
- 推论：
  1. 窗口大≠可以全塞（B⑧：成本/注意力/时效/权限四理由）
  2. 重要信息**位置**有讲究（开头/结尾好，中间差）→ 压缩策略保 head+tail（A⑧ 的模型侧依据）
  3. 长上下文评测要按"信息在什么位置"分层（大海捞针按深度分层的做法）

## S4 推理成本模型（J 课的理论底座）

- **输入 token 与输出 token 不同价**：输出通常是输入的 3-5×（decode 慢+每 token 全模型前向）→ 优化"少说废话"和"少送上下文"同等重要
- **caching 折扣**：命中前缀按折扣价（J 课 S3）
- **每任务成本公式**（面试能手推）：`Σ over steps (input_t × p_in + output_t × p_out) × 步数`——agent 成本=单步成本×**步数**，步数是唯一能乘数放大的项 → 少步比省字值钱（C 课"能用 workflow 不用 agent"的成本注脚）
- 长上下文的非线性：KV cache 显存↑ → 并发↓ → 单位成本↑（S1 推论 2 的定价版）

## S5 微调意识（什么级别：时机+类型+取舍，不碰训练）

| 技术 | 一句话 | agent 场景位置 |
|---|---|---|
| SFT | 用示范轨迹教行为 | 高质量轨迹积累后（K 课 S5）：把提示词里反复教的行为烘进权重 |

## S7 八股速查表（16 题 × 3-5 行标准答案）

> 🔶1 补入（2026-10-11）。用途：面试前 30 分钟过一遍 + 被追到时秒答。全部为经典稳定知识、无版本敏感；个别工程数值是量级参考，不当精确承诺。

**词法**

1. **BPE 算法？** 字符级起步，反复合并语料中频率最高的相邻 token 对，直到词表达标。为什么用：OOV 可控（生词拆成已知子词）、词表从指数级压到几万-几十万、子词带来泛化。
2. **SentencePiece 和 BPE 的区别？** BPE 吃分好词的流；SentencePiece 直接吃原始文本（空格是特殊符 ▁），语言无关（CJK 直接可用）——LLM 训练的实际形态。
3. **为什么不纯字/纯词？** 纯词=词表大+OOV 爆炸；纯字=序列拉满（n² attention 成本直接放大）。子词=覆盖与长度的工程折中（英文常见词 1-3 个子词）。

**架构**

4. **MHA / GQA / MQA？** MHA 每头独立 K/V；MQA 全体共享一组；GQA 分组共享（折中）。目的同一：**减 KV cache** → decode 内存带宽/成本（S1 推论 1 的架构侧手段）。LLaMA-2 70B / Qwen / Gemma 用 GQA。
5. **MoE 原理与代价？** FFN 换成 N 个 expert，router 每 token 选 top-k → 总参数↑但单 token 计算恒定。代价：负载均衡不稳（辅助 loss）、expert 间通信、显存装 expert。Mixtral / DeepSeek 系。
6. **attention 为什么 O(n²)？** 注意力矩阵 = seq×seq（每 token 看所有 token）。缓解：滑动窗口（Mistral SWA）、稀疏/线性 attention（研究线）；工程界的现实做法=窗口硬限制+上下文压缩（A 课 ⑧）。**这就是"窗口是硬约束"的模型侧根源**（S3 推论 1）。

**损失与训练**

7. **CE 和 KL 各管什么？** CE=下一 token 预测的标准损失（teacher=数据）；KL=两个分布的距离 → 蒸馏（student 对齐 teacher 分布）+ RL 的 KL 正则（防 policy 偏离参考模型太远——RLHF/GRPO 目标函数里都有这一项）。

**RL 对齐（谱系按"省掉了什么"记）**

8. **RLHF 标准链？** SFT（监督模仿）→ 偏好对训 RM（学习的打分器）→ PPO 以 RM 为奖励微调。InstructGPT（Ouyang et al. 2022）。
9. **PPO 为什么工程重？** 四个模型同驻显存（policy/reference/reward/critic）；超参敏感；reward hacking（模型钻 RM 空子）。
10. **DPO 简化了什么？** 把 RL 目标闭式化成**偏好对上的监督式损失**：省掉显式 RM 训练和在线采样。代价：没有在线探索、对偏好数据质量依赖更重。
11. **GRPO 省了什么？**（DeepSeek）去掉 critic：同 prompt 采一组响应，用组内均值当相对 baseline 估 advantage → 省 critic 显存，适合大规模 RLVR。
12. **RLVR？** 奖励=可验证信号（测试通过/数学核对/格式校验），不需要 RM。**coding 模型对齐的主形态**（SWE-bench 类评测=它的外显）；边界：只在"奖励可便宜验证"的任务成立。

**推理服务**

13. **continuous batching？**（Orca）decode 阶段每迭代动态插入/移除请求，不等整批跑完 → 利用率↑（量级 2-5× vs static）。前提=逐请求 KV 管理（vLLM PagedAttention：KV 分页、减碎片）。
14. **speculative decoding？** 小模型（draft）先写 k 个 token → 大模型一次前向**并行验证** k 位 → 接受最长正确前缀。无损（输出分布不变）、decode 加速 2-3×；接受率取决于两模型分布相似度，成本=draft 开销。
15. **GPTQ / AWQ / FP8 区分？** GPTQ=逐层二阶（Hessian）误差校正的后训练量化，W4A16；AWQ=激活感知，保护"重要通道"（激活大的权重保高精度），W4A16；FP8=硬件原生精度（H100+），训练推理通吃。记法 W4A16=权重 4bit × 计算 16bit。

**长上下文**

16. **8K 窗口怎么外推到 128K+？** RoPE 把位置编码成旋转（相对位置+长程友好）；外推=YaRN/NTK 式：插值 RoPE 基频 θ + 校正 attention 温度。**为什么不是白给的**：模型没训过超长位置，质量随长度衰减（S3 context rot 的机理）——外推买到的是窗口，不是质量。

**跨课定位（已有章节，一行带过）**：prefix caching=J 课 S3（KV 复用+计费折扣）；temperature/top-p/seed=S2（结构化输出低温、评测固定 seed）；KV cache 公式=S1（2×layers×kv_heads×head_dim×seq_len×bytes）。
