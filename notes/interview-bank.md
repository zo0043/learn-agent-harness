## 1. 30 秒自我介绍框架（资产→故事→证据，背到 90 字内）

> "我做过三个和 agent 直接相关的事：**从零手写过一个最小 harness**（loop/工具协议/权限门/崩溃恢复，TS+Python 双版可运行）；**跑过一个生产级 LLM 批处理系统**（FinHot：1800+ 行轨迹台账、T+5 延迟评测、失败率治理、两轮提示词消融迭代）；**正在把生产事故变成系统知识**（一起并行会话污染生产的事故，让我把权限层和执行沙箱拆成两道独立的门，并建了可重放的事故测试）。"

三句话=三个层次：能写（A）/ 能上生产（FinHot）/ 能从事故长出机制（E）。**每句后面都跟着一个可展开的 3 分钟故事**——自我介绍就是目录。

## 3. 项目深挖题库（每个故事一个"追问链"，追问到底=合格线）

### 3.1 FinHot 幽灵事故（权限/沙箱/事故响应，最稀缺故事）
- Q1 事故完整时间线？18:00-18:25 之间你做了什么？
- Q2 为什么并行会话能碰到生产？目录/容器/命名空间各缺了什么边界？
- Q3 "动容器前查创建时间"这条规则防什么、不防什么？（事前 vs 事后）
- Q4 如果重做一次，架构上怎么让这类事故**不可能**发生？（沙箱池/compose 项目隔离/worktree——沙箱与凭据 §S1/S3）
- Q5 事故里数据面受影响吗？你怎么验证的？

### 3.2 FinHot labeler（评测/状态机/延迟奖励）
- Q1 为什么 T+5 而不是 T+1？（金融数据的噪声/交易日历）
- Q2 858 条 skipped 各是什么？分母怎么写才不会骗人？
- Q3 方向准确率 vs baseline，baseline 怎么定义的？n≈60 够吗？
- Q4 labeler 跑挂了怎么办？（幂等/upsert/durable execution）
- Q5 这个系统和 SWE-bench 式评测的本质区别？（延迟奖励/真实世界结果）

### 3.3 backfill 1645 行（长任务/失败治理）
- Q1 失败率 ~10%，失败分几类？各自处置？（超时/订阅异常/…）
- Q2 断点续跑怎么实现的？幂等键是什么？
- Q3 为什么不在失败时原地重试到成功？（退避/全局预算/次日续跑）
- Q4 如果 1645→164500，先改什么？（并发/队列/限流——API 与多模型路由）

### 3.4 harness-demo（白板能力的运行版）
- Q1 四种运行模式各证明了什么？crash 模式怎么注入的？
- Q2 19:33 的代理 400 事故你当时怎么定位的？（provider 是组件）
- Q3 你的 policy 如果默认 allow，幽灵事故会怎么重演？
- Q4 压缩策略里 head/tail 怎么定？约束丢了会怎样？(模型基础:位置效应)

### 3.5 rag-demo（检索+评测实操）
- Q1 为什么用 hash embedding 不用语义模型？（代理 503 + 可复现/可打印的教学价值——要敢承认局限）
- Q2 recall@5 唯一漏题错在哪？（paraphrase 探针=词法路极限）
- Q3 BM25 的 IDF 定价怎么解释"什么"这种高频词？（rag.md §13 发现 1）
- Q4 换真 embedding 模型要改几行？为什么架构不用动？（Embedder 接口）

## 8. 行为面试（Behavioral）准备（🔶5 补入 2026-10-11）

> 行为题考的是"可预测的处事方式"，不是事件本身。**Action 层必须是"我"不是"我们"；Result 层必须有数字；Learn 层必须给可迁移规则**。
> 诚实定位：我的工作以 solo/小团队为主 → "冲突"的形态是**技术取舍**不是人际摩擦——主动说破这一点，不编造人际戏剧（编造在追问下必穿）。

### 模板（单题 ≤90 秒：S 10% / T 10% / A 50% / R 20% / L 10%）

| 层 | 要求 | 常见翻车 |
|---|---|---|
| S | 一个场景，带约束（时间/资源/赌注） | 前奏太长 |
| T | 为什么难、为什么是我做 | 和 S 重复 |
| A | "我做了 X"×3-5，按**决策→行动→验证**顺序 | 全是"我们"；只报结果不报决策过程 |
| R | 数字（10% 失败率、1830 行、15×→恢复、25 分钟） | "效果显著" |
| L | 可迁移规则（下次遇到同类怎么办） | "我学到很多/更谨慎了" |

### 五道标准题（骨架+红线）

**Q1 你克服过的最大挑战** → 幽灵事故（沙箱与凭据主线，最稀缺故事）
- S：2026-10-09 18:00-18:25，并行会话误删重建生产容器，进程面被污染
- T：数据面完好但运行时全乱，要同时做范围判定、恢复、防再发
- A：① 按容器创建时间定位污染范围（数据面 vs 进程面分离）② 18:25 重建 worker/api（main 5caa4ed）③ 把权限层与执行沙箱拆成两道独立门 ④ 建了可重放的事故测试
- R：25 分钟恢复、零数据丢失；事故变成 沙箱与凭据教材+一条进规则的防御（"动容器前查创建时间"）
- L：权限模型必须区分"谁在调"与"在哪执行"——一道门防不住两类威胁
- 红线：不甩锅"另一个会话"——边界缺失是我的流程责任；不展开无关技术细节

**Q2 你的一次失败** → litellm 15× 劣化（API 与多模型路由 §S5 事故实录）
- S：10-01 起网关 p50 10s→146s、频繁 EOF，52% 文章失败
- T：吞吐 1200 篇/日→150-280，且**我一开始没发现**——靠全面检查才暴露
- A：① 全量健康检查（延迟/失败率/吞吐三视角）② 把失败分类（瞬时窗口自愈 vs 持续性）③ 定"连续 10 败→熔断+告警"阈值 ④ 重试预算改全局共享
- R：形成降级阶梯（主→备→降级→跳过）+ 阈值表（API 与多模型路由 §S5 的完整内容）
- L：**监控缺位本身就是失败**——没测的东西等于不存在
- 红线：不以"后来自己好了"收尾——失败故事必须以机制收尾；不掩饰"一开始没发现"（那是题目要点）

**Q3 一次冲突/技术分歧** → rag-demo 的 hash embedding 取舍（诚实版）
- S：RAG 与检索实操需要 embedder，代理的 embedding 模型 503 不可用
- T：正解（真语义嵌入）跑不了，两条路：等 vs 用可复现的 hash embedding
- A：① 选 hash（FNV-1a 768 维），**并把局限写进复盘** ② 用评测量化局限（recall@5 唯一漏题=paraphrase 探针=词法路的极限）③ Embedder 接口化——换真模型不改架构
- R：recall@3=1.00/@5=0.94，漏题定位到机制层而非糊过去
- L：资源受限时，"可复现的近似+已知边界" > "不可解释的黑盒"——工程选型先保可验证性
- 红线：不编造人际冲突；"我 solo 工作，冲突表现为技术取舍"本身就是成熟答案；不贬低"正解"

**Q4 为什么做 agent 开发 / 为什么这个方向？**
- 三件套（30 秒版自我介绍的展开）：从零写 harness（能写：从零手写 harness）+ FinHot（能上生产：1830 行台账/T+5 评测/失败治理）+ 沙箱与凭据（能从事故长机制）
- 差异化一句："我亲手从零建过，所以知道框架藏了什么（框架生态 §S2）——用框架选的是默认决策，弃框架的代价我算得出来"
- 红线：不说"我想做自己的 agent 产品"（这是工程师岗）；不说"agent 是未来"（空话，没有信息量）

**Q5 为什么想来我们公司？**（面试前作业，每家公司单独填）
- ① 对其产品/工程博客的具体观察（一句，必须具体到功能）② 与我的资产共鸣的一点（如：他们接 OTel ↔ 可观测 / 他们做 MCP 生态 ↔ MCP 与供应链安全）③ 一个诚实的 gap+我怎么补
- 红线：不说"想来学习"（学习是我自己的事，不是雇我的理由）；不查资料就说（沉默 > 空话）；不贬低现东家/前选择

### 演练规则（接 §2 演练规则）

行为题的卡壳点通常在三处：① A 层说成"我们" ② R 层没数字 ③ L 层停在"更谨慎"。每轮模拟后按这三点自查。
