# 教学型正文规范（sprint 2 起沿用）

> 本文是「课程笔记 → 教学型正文」的统一规范，供 P1–P4 逐课深度终稿沿用（当前从 sandbox / mcp 起步）。
> 一条总原则：**讲义是给「会读文档的人」看的，正文是给「能跟着跑出结果的人」用的**——每个结论都能落到一个可复现判据上。

## 1. 正文骨架（一条主线，八段）

按「由浅入深」组织，顺序固定，缺一不可：

```
① 开篇一句话定位   → 这课解决什么问题 + 收口哪个 MVP（读者 10 秒判断该不该学）
② 预备知识段        → 课程之外的技能门槛（区别于 prereqs 课程依赖，见 §2）
③ 为什么（事故/问题）→ 一个具体代价：不讲原理，先讲「不学这课会炸在哪」
④ 机制（分层/代码）  → 逐节「代码 + 讲解」：怎么实现、每段在防什么（§4）
⑤ 怎么跑出来（MVP）  → 每节收一个实跑判据，最终收口一个 clone 判据（§5）
⑥ 失败模式/陷阱      → 每节一个「最常见的错」+ 值得自查的点（为什么差一点就炸）
⑦ 常见错误与自查清单 → 每条对应一个真实踩坑点
⑧ 来源与锚点        → 事实、代码、一手源的出处（数字可复核）
```

`③④⑤` 是主干，`③` 必须先于 `④`——先让读者有「这是个大祸」的体感，再讲机制才不会空转。

## 2. 「前置知识段」与「prereqs 课程依赖」是两回事

| 维度 | prereqs（课程依赖） | 前置知识段（技能门槛） |
|---|---|---|
| 存哪 | `course-structure.ts` 的 `prereqs[]` | 正文「预备知识」段 + `prerequisiteNote` 字段 |
| 语义 | 硬依赖：必须先把那门课学完 | 概念/技能门槛：会 X 才能跟上，但 X 不一定是本课程体系里的课 |
| 例子 | mcp 的 `prereqs=["sandbox"]` | mcp 的「HTTP/JSON-RPC + 客户端-服务器模型」 |

**前置知识段三要素**（紧跟在定位句之后）：
1. 承接句：上一门课带来什么直觉（如「上一课 sandbox 的 policy 门/egress 直接复用」）；
2. 门槛句：会什么概念/命令即可（0 经验的课写「会 X 即可，无需 Y」）；
3. 减压句：什么不需要提前会、跟着 demo 边跑边建（如「不要求会写容器，四通道直觉随 sandbox-demo 建立」）。

## 3. `prerequisiteNote` 写法（course-structure 元数据，一句话）

对照 P0 已精化的口吻（`harness-from-scratch` / `rag`）：

- 进入门槛 + 不需要什么，一句话写完；
- 0 经验课用「0 经验可入手：会 X 即可，不要求懂 Y」；
- 有前置课的用「已…（上一课带来）+ 只需 Z 的粗概念——机制随 demo 边跑边建」。

## 4. `practicalOutput` 写法（course-structure 元数据，三件套）

必须覆盖三件事，缺一不可：

1. **交付对象**：独占 `xxx-mvp`（或复用谁的 MVP / 横向资产）；
2. **clone 判据**：`cd <demo> && npm i && npm run demo` 复现什么**可断言**输出（跑得起来 = 哪几条断言通过；给测点不给会漂移的硬编码 hash/digest）；
3. **复用/扩展关系**：后段哪几门课复用/扩展这份代码/方法论。

范例（已收录）：

```text
交付 sandbox-mvp（独占）：四通道 policy 引擎 + 幽灵事故重放剧本。
判定 clone 能跑 = cd sandbox-demo && npm i && npm run demo 复现「A 组仅权限门→生产被替换 /
B 组四通道+沙箱→生产正常」+ `✅ 重放一致性断言通过`（A/B 各 3 次逐字节一致）；
mcp/durable-execution 复用它的 policy 门与「事故重放」方法论。
```

## 5. 逐节「代码 + 讲解」组织

- **贴**：能从 demo 源码贴的，贴**真实、可运行**的关键片段（函数级，≤ 20 行），并标文件路径；
- **讲**：每段代码紧跟一段「这段在防什么 / 为什么这么写 / 失败模式 / 值得自查的点」——代码是锚，讲解是价值；
- **不能贴的**（框架概念、协议线、隔离谱系）：用表/图把机制讲透，并回指一次 demo 源码里对应哪一行。

代码引用纪律：以 `*.ts` 源码为准，不以记忆为准；引用里写文件 + 函数名，读者可 `cd <demo>` 对着读。

## 6. MVP 实跑判据口径（统一三态）

每个大节收一个「实跑判据」，最后收口一个 clone 判据：

- **确定性**：同一输入 → 同一输出（mock/预置表/逻辑时钟，抽掉墙钟与随机数）；
- **可机器核对**：有明确断言行（`✅ …` / `❌ …` / digest / sha256），不靠人肉读输出；
- **可重放**：跑 N 次逐字节一致（这是「可复现」的证据，不是「跑过一遍」）。

给 clone 判据时：给「哪个断言打印行」+「node ≥ 18」这类硬前提，**不给会随版本漂移的具体 hash/digest 数值**（数值属于正文「来源与锚点」，随 demo 版本更新）。

## 7. 事实与正确性纪律

1. 改写只动「教学组织」，不动「既有事实」：事故时间线、四通道语义、MCP 原语、spec 版本线、OWASP 条目号、recall/sha256/digest——一律回查 notes 原文 / demo 源码，不凭记忆。
2. 发现原文事实错误：**就地划改正文**，不追加「这里写错了」的说明（读者从摘要读入会重新激活旧错）。
3. 拿不准的事实：回查源码/一手源；查不到就显式标「待核实」，不冒充已核实。
4. 术语锚点：库内 `#NN` 编号保留（内部引用），对外讲课时用「课程名 §节号」（如「沙箱与凭据 §S2」）。

## 8. 改稿检查清单（每课收尾自检）

- [ ] 八段骨架齐全，`③为什么` 在 `④机制` 之前；
- [ ] 预备知识段三段（承接 / 门槛 / 减压）齐全，且与 `course-structure.ts` 的 `prerequisiteNote` 一致；
- [ ] 每个大节有「代码 + 讲解」且代码标了文件路径；
- [ ] 每节收一个实跑判据，clone 判据含三件套（交付/判据/复用）；
- [ ] 事实回查 demo 源码，无凭记忆改写，无数字漂移；
- [ ] 失败模式/自查要点至少各一节；
- [ ] `esbuild bundle + node 断言`（或 `tsc --noEmit`）通过。
