# 毕业项目设计（生成层收口：开放命题 + 验收判据 + 自测引导）

> sprint 6 开题。定位：主线 `my-agent` 走完 M0–M4（补全层）之后的**第三跳——生成层**。M0–M4 练的是「实现已知模块」（教师给定签名 + 预期 + TODO 切分）；毕业项目练的是「从模糊需求自己拆模块、定接口、写验收」的**设计能力**。所以本页**只给命题、判据、引导，不给 starter / TODO / 参考答案**。
> 前置：`notes/capstone-blueprint.md`（主线全局六栏）+ `notes/capstone-style-guide.md`（断言三态）+ `my-agent/exercises/m0..m4` 与 `assert/m0..m4.assert.ts`（你亲手补全过的机制）。

## 1. 三步技能层级的收口

| 层 | 练什么 | 你拿到什么 | 判据来源 |
|---|---|---|---|
| ① 追踪（track） | 看懂老师搭好的确定性 demo | 完整可跑源码 | demo 自带的断言 |
| ② 补全（complete） | 把给定签名 + 预期的 TODO 补对 | `starter`（半成品）+ `solution`（参考答案） | `assert:m<N>` 三态 |
| ③ **生成（generate）** | **从模糊需求，自己拆模块、定接口、写验收** | **只有命题 + 判据 + 引导** | **你自己写的 `assert` + 黑盒/白盒判据** |

毕业项目落在第三层。它与你已经掌握的 M0–M4 机制**能力衔接**（你用那些机制来达成命题），但**不重复任何脚手架**——M0–M4 的 `types.ts`/`loop.ts`/`policy.ts`/`assert` 都不复制过来；你从一个空目录起步。

## 2. 生成层纪律（不可违反）

> **一句话纪律：本页不提供 starter/TODO/参考答案，学员从空目录起步。**

- **不给 starter**：没有 `types.ts` 骨架、没有 `loop.ts` 签名、没有半成品文件等你补函数体。
- **不给 TODO**：没有 `TODOError`、没有「剪除处」、没有「补全这一格」的提示。
- **不给参考答案**：没有 `solution/`、没有「正确实现长什么样」、没有一行可抄的实现 hint。
- **只给**：命题（要解决什么）、验收判据（怎么算对）、自测引导（怎么判断自己对没对）。
- **你从空目录起步**：目录结构、模块拆分、函数签名、数据流向，全部你自己定。判据只看「行为对不对 + 机制齐不齐」，不看你「怎么写的」。

> 判据里若出现「用 XX 文件」「调 XX 函数」，等于把参考答案塞进了判据——**禁止**。判据只能描述可观察行为（黑盒）与「必须存在的机制类别」（白盒）。

## 3. 命题（三选一，都是「模糊到需要你拆、又具体到能写验收」）

每条给「要解决什么」+「判据锚点」，但**不说怎么拆模块、定什么接口**。选一条即可；想叠加两条属加分项。

### 命题 A · 个人研究助理（research-assistant）

> 做一个能处理「查资料 → 记笔记 → 定时提醒」三类任务、带权限门、能对 golden set 自评、崩溃可恢复的个人助理 agent。

- **要解决**：用户给一句话意图（如「查 LLM 发展史的三个转折点并记下来，明天提醒我复习」），agent 判断走哪类任务、执行、把结论写进可回忆的笔记、并支持「定时提醒」这类带时效的状态。
- **判据锚点（留给黑盒）**：① 三类意图各有一个端到端「输入意图 → 预期输出」确定性断言；② 危险动作（如「删除笔记」/「外发内容」）须被权限门拦下且副作用未发生；③ 模拟崩溃后重启，已执行的记笔记副作用恰好一次；④ golden set（你自定若干意图→期望分类/输出）自评达标。
- **白盒要素侧重**：loop + 多工具 + 记忆（M4）+ 权限门（M1/M2）+ 可恢复（M3）。「定时提醒」可以用逻辑时钟/预置表模拟，不必真连时间服务。

### 命题 B · 仓库巡检门禁（repo-guard）

> 做一个读代码变更、跑检查、写报告、并给出放行/拦截结论的巡检 agent，带沙箱边界、golden 评测、可观测。

- **要解决**：给一批「代码变更记录」，agent 读取 → 按规则检查（如「改了高风险路径」/「无测试覆盖」）→ 写结构化报告 → 输出「放行 / 拦截」+ 理由。
- **判据锚点（留给黑盒）**：① 给定变更集 → 断言报告字段齐全 + 放行/拦截结论正确；② 危险变更（如「删除关键文件」）应触发沙箱/越权边界拒绝而非静默放行；③ golden set（若干变更集→期望结论）自评精确率/召回率达标；④ 跑一遍能打印结构化 trace/log 摘要（可观测）。
- **白盒要素侧重**：loop + 多工具 + 沙箱边界（M2）+ 评测（M2）+ 可观测（M3）。

### 命题 C · 带噪信号的方向判断器（signal-arbiter）

> 做一个从带噪 label 里做两轮降噪、门禁把关、给出方向提案并附成本意识的判断器，带飞轮、模型意识、可恢复。

- **要解决**：给一批「带噪标注的信号样本」（含杂质、重复、缺失），agent 做降噪 → 聚合指标 → 门禁判断「这轮改动到底该不该采纳」→ 输出提案/驳回 + 数值依据（含成本/显存意识）。
- **判据锚点（留给黑盒）**：① 给定带噪样本 → 断言降噪后（去杂/去重）+ 门禁结果正确；② 门禁输出只有「提案/驳回」两态，不存在「自动生效」态（禁 auto-apply）；③ 触发一次「一次只动一个变量被破坏」的输入 → 断言报错（降噪前提不被打破）；④ 崩溃恢复后已统计的指标收敛（侧作用恰一次）。
- **白盒要素侧重**：loop + 评测飞轮（M4）+ 模型成本意识（M4）+ 可恢复（M3）。

## 4. 验收判据清单（黑盒 + 白盒两类，都可判定）

判据只管「对不对」，不管「怎么实现」。**黑盒** = 给定输入 → 断言输出（行为）；**白盒** = 成品必须含哪些 M0–M4 机制（要素），各配一条**可判定检查**（检查「有没有」+「你指认它在哪」，不检查「写得合不合理」——写得好不好由黑盒断言兜底）。

### 4.1 黑盒判据（可观察行为，5 条）

| 编号 | 判据 | 可判定检查 |
|---|---|---|
| B1 确定性 | 同一输入连续两次运行，输出逐字节一致（无墙钟 / 无未固定 seed 随机 / 无真实网络） | 同一命令跑两遍 `diff` 空 |
| B2 主任务跑通 | 命题给定的端到端「输入 → 预期输出」成立（至少覆盖命题里的主场景） | 你的 `assert` 脚本里有一条该场景断言，exit 0 |
| B3 权限/沙箱拦停 | 一个危险/越界动作被拒，且**副作用未发生**（不是「先做了再补救」） | `assert` 里注入危险动作 → 断言「被拒 + 状态未变」 |
| B4 崩溃可恢复 | 模拟中断后重启，已完成的副作用恰好一次（幂等收敛，不多做不丢做） | `assert` 里跑一半抛错 → 重启续跑 → 断言副作用计数 === 1 |
| B5 评测自评 | 你自定的 golden set（≥ 3 条），recall / precision（或等价质量指标）达到你声明的达标线 | `assert` 里跑 golden → 打印指标 + `✅`/`❌` + exit 0 |

### 4.2 白盒要素（成品必须含的 M0–M4 机制，7 条）

每条机制都是 M0–M4 教过的；**判据只要求「存在」+「你在自述里指认位置」**，实现方式完全自由。

| 编号 | 机制（来源 milestone） | 可判定检查（你在自述 MANIFEST 里指认） |
|---|---|---|
| W1 loop | 「想 → 做 → 说 → 终止判定」显式循环（M0） | 指认循环控制 + 终止判定的 file:函数 |
| W2 多工具 | ≥2 个工具按名字分发（M1） | 指认工具注册/分发处 + 列工具名 |
| W3 权限门 | 默认 deny / 白名单 / 多通道（其一）（M1/M2） | 指认「未授权即拒」的判定处 |
| W4 评测 | golden set + 可跑断言命令（M2） | 指认 golden 样本 + `assert` 命令 |
| W5 可恢复 | journal / checkpoint / 幂等键（其一）（M3） | 指认持久化 + 恢复判定 + 幂等收敛处 |
| W6 可观测 | span / metric / 结构化日志摘要（其一）（M3） | 指认埋点处 + 打印的结构化摘要 |
| W7 收口闭环 | 记忆 或 评测飞轮 或 模型成本意识（M4 三选一） | 指认你选的 M4 能力 + 它在哪 |

> 「指认」不等于「解释实现」——你在成品目录写一份 `MANIFEST.md`，逐条填「W<k>：file:函数 + 一句它为什么满足」。判据运行器只检查「七条 W 都被指认了」，不检查指认内容对不对（对不对由 B 系黑盒断言兜底）。

## 5. 自测引导（把 M0–M4 的「断言/确定性/可机器核对」迁移成「判自己成品对错」）

三步，先粗后细：

1. **先黑盒跑通**：断言一行都别写，先让成品对 2–3 个手工输入跑通（一个主场景 + 一个危险动作）——「能跑通」优先于「写得好」。跑不通先拆到能跑。
2. **再白盒自查**：对照 §4.2 七条，逐条写 `MANIFEST.md` 指认你的实现位置。哪条指不出来，就是那类机制没落地（或你写在了但你不知道算不算是它——回到对应课的 demo/主线 M<N> 去对照「机制长什么样」）。
3. **再补断言**：把第 1 步的手工输入固化成确定性断言（B1–B5）：输入预置常量 / 逻辑时钟 / 固定 seed，无墙钟随机；每条一个 `✅`/`❌` 打印；`assert` 连跑两次 `diff` 空。这是从「我感觉对了」到「机器说对了」的最后一步。

## 6. 毕业判据（一句话收口）

**成品能跑 + 黑盒断言过（B1–B5 全 ✅、exit 0）+ 白盒要素齐（W1–W7 全指认）** —— 满足即毕业。

> 一句话收口：**「你搭出的这个，与 M4 的 `my-agent` 同级——同样的确定性、同样的权限/评测/可恢复/可观测纪律——且它是你从空目录、从模糊需求、独立设计出来的。」**

## 7. 红线继承与「可选真实调用」的边界

- **继承（必须）**：成品默认全离线、零 key、零外部网络，确定性底座（无墙钟/未 seed 随机 real），判据可机器核对、可重放——与 M0–M4、与 17 demo 同一纪律。
- **放宽（可选加分，不设墙）**：学员**可自由选**接真实模型 key / 真实数据源，把「离线 mock 判据」换成「真实调用」——这是加分项、不是毕业门槛；判据运行器不因「没接真实 key」判不及格，也不因「接了」额外加分（判据只认 B1–B5 行为 + W1–W7 要素）。若接真实 key，须在 MANIFEST 里自述「哪些判据从离线 mock 换成了真实调用、确定性（B1 可重放）如何收窄」。
