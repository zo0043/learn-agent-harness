## 一句话定义

每个行动携带隐式决策，并行写者必然产出风格/边界冲突的碎片——2026 年唯一被确认能工作的模式是"多智能体出智力、写操作保持单线程"，并行只在"写单线程、读多路"时产出一致工件。

## 为什么影响走向

这是 Cognition 从 2025「Don't Build Multi-Agents」到 2026 修正立场的分水岭：问题不在多智能体"笨"，而在并行写出的工件不一致——每个 agent 的行动都携带隐式决策（选了什么风格、划了什么边界），写者一多决策就互相打架。反直觉发现：代码评审循环在评审 agent 与编码 agent 零共享上下文时效果最好（Devin Review 平均每 PR 抓 2 个 bug，58% 严重级）。这条判断决定多智能体系统能不能产出"可交付工件"，而不只是更贵的并行。

## 行业一手源

Cognition《Multi-Agents Working》（2026）：确认唯一能工作的模式是"多智能体出智力、写操作保持单线程"，零共享上下文的评审循环效果最好（Devin Review 平均每 PR 抓 2 个 bug、58% 严重级）。（前史：《Don't Build Multi-Agents》2025——行动携带隐式决策，并行写必然冲突。）

## 面试一句话

"我让多智能体并行做研究和评审、但写保持单线程——每个行动携带隐式决策，并行写只会产出风格与边界都不一致的碎片。"
