### 1.4 内容大纲（写到能照抄的粒度）

`### S5.1 跨窗口接力：compaction 不够，初始器 + 编码代理 [2026现行]`

1. **这一节解决什么问题**：S2–S4 的 journal/checkpoint/幂等管「一个任务内崩了能续」；S5 管「长跑不烂」。但还有第三个问题在更下面：**上下文窗口本身有上限，复杂任务无法在单个窗口内完成**——每个新会话都从零开始，前一个窗口做了什么、为什么这么做，全部丢失。compaction 只压缩**一个**窗口内的历史，管不了**窗口之间**。
2. **Anthropic 的实证（2025-11-26）**：Opus 4.5 + Claude Agent SDK 循环跑，只给"克隆 claude.ai"这种高层提示词 → 建不出生产级应用。两类失败：① 试图一次做完（one-shot），上下文在中途耗尽，下个会话面对半成品只能猜；② 后期会话看到"有进展"就宣布完成。
3. **两件套（表）**：
   | 角色 | 何时跑 | 做什么 | 留下的artifact |
   |---|---|---|---|
   | initializer agent | 第 1 会话 | 按 spec 搭环境、生成 200 特性清单（全 failing）、init git | `feature_list.json` / `init.sh` / `claude-progress.txt` / 初始提交 |
   | coding agent | 每会话 | 先读 git log + progress + 特性清单 → 选最高优先未完成项 → 增量实现 → 跑测试 → 提交 + 更新清单 | 干净现场 + 描述性提交 + 进度文件 |
4. **与 durable execution 的关系（本课差异化句）**：journal/checkpoint 是**进程级**接力（同一条任务状态）；initializer/coding 是**任务级**接力（跨天/跨窗口的工作分配）。前者保证"副作用不多不少发生一次"，后者保证"下一个窗口知道上一个窗口干了什么"。**文件系统 = 跨窗口的共享内存**（呼应 从零写 harness §⑥ JSONL、Harness 架构 §5）。
5. **防误读框（引用文章脚注）**：两个"agent"只是初始提示词不同，harness/工具/system prompt 完全一致——**这不是多智能体**，是同一 harness 的两种开场提示词。多智能体的"何时不要用"见 多智能体编排 §S9。
6. **失败模式**：把跨窗口状态只放 prompt 不放文件（会话一死全丢）；特性清单没有"完成定义"（agent 自评通过 = 假绿灯）；不要求每会话留干净现场（下个会话先修上个会话的烂摊子）。

**可用事实（逐条可追）**：
- arXiv 2601.06007（Lumer 等 7 作者）：在 **DeepResearch Bench**（多轮 agentic benchmark，agent 自主执行真实 web 搜索工具调用）上跨 **OpenAI/Anthropic/Google 三家**、**500+ agent sessions**、**10,000-token system prompts** 实测：prompt caching 降 **API 成本 41–80%**、降 **TTFT 13–31%**。三种缓存策略对比（全量上下文 / 仅 system prompt / 排除动态工具结果）：**战略性 cache block 控制**（动态内容放系统提示**尾部**、避免动态 traditional function calling、排除动态工具结果）比 **naive 全量缓存**收益更稳——naive 全量缓存**甚至可能增加延迟**。消融：prompt 500–50,000 token × 工具调用 3–50 次，超过 provider 最低缓存 token 门槛后收益呈线性。

### 8.3 归档方案（三件事）

1. **图录（figure index，生成器而非手抄）**：新增 `site/tools/figure-index.mjs`（node 内置模块、秒级、可本机跑）：扫 `notes/**/*.md` 的每个 ` ```mermaid ` 块，输出（域/文件:行号/图型/所属最近标题）全量表，落到 `notes/process/figure-index.md`（过程文档位，被 `site/src/content/config.ts` 的 `pattern:'*.md'` 挡在课程路由外——按 `notes/knowledge-map.md:13` 的既定分层）。**「按域归档」的物质承担者就是这张表**：域 = 15 知识域 + 2 横向资产（口径同 knowledge-map.md:12）。
