## 3. 写死值 / 硬编码全清单

判定分四类：
- **合规派生**：声明值/期望值从真源（口径块 / notes / 文件系统实测 / 源码解析）得出，脚本不自己编数；
- **违规自编**：现值或期望值以字面量写死在脚本里，违反 `check-counters.mjs:18`「脚本内不硬编码任何计数」的同款精神；
- **结构性常量**：路径、超时、正则、断点等工程参数——设计约束 2 只禁「计数」，此类合规，但会随结构演进而腐化的单独标注；

### 6.1 变异测试制度化（每个门禁应有「故意破坏能被抓」的自证）

2. **check-counters 新增 `--self-test`**（ spawnSync 子进程模式，仿 check-classes:83；每次变异 = 把某判据的真源临时改坏后跑一遍，期望 exit 1）。必测变异集（至少 4 个）：

### 6.2 派生链一致性（真源 → 副本 → 站点渲染，三层核对）

**现状**：第一层（真源）+ 第二层（副本）已有机器判据（check-counters 3b/3c、check-corpus 全副本扫描）；**第三层（站点渲染值）无机器判据**——本机禁 build 之外无覆盖，CI 的 Build sanity 也只断「dist HTML=32 + 关键页非空」（`verify.yml` Build sanity 步），不断言「页面上显示的数字 = 真源」。

**实证缺口（P1）**：
1. **两个 COURSE_COUNT 双源漂移无人抓**：`site/src/data/courses.ts:131`（COURSES 过滤）与 `site/src/data/course-structure.ts:390`（COURSE_STRUCTURE 长度）是**独立推导的同义常量**（当前实算均为 17，一致）；`index.astro:15` 消费前者、`nav/learn/works/[slug]` 消费后者。任一文件加课漏同步另一文件 → 页面「17 课」与课程列表数不一致，**无判据**。建议新增判据：两常量的推导结果必须相等（都从源码实算，双源互校）。
2. **站点渲染层数字断言（CI 侧，P2）**：Build site 后 grep dist HTML，断言关键页面出现的口径数字与口径块一致（如首页「{COURSE_COUNT} 课 · {DOMAIN_COUNT} 个知识域」`index.astro:50`、`ragStats.ts` 解析出的 recall 三值组）。这守住「常量算对但渲染接错」的一类漂移。**注意**：此断言只能在 CI 构建产物上做（本机禁 build）；HTML 内数字的上下文匹配需防误伤（留浏览器目检兜底审美，数字本身可机检）。

### 6.3 真源-副本双向核对（不只「副本含真源值」，还要「副本不含非真源值」）

**现状缺口（P1，两个活例）**：
1. `check-counters.mjs:403-412` 的 `grepNum` 是**存在性匹配**（副本里能匹配到真源值即过）——README 若在非沿革段另写「19 篇课程内容」，判据仍绿（「18 篇课程内容」仍在场）。**「副本含真源值」≠「副本只含真源值」**。
2. `check-corpus.ts:61-70` 的副本扫描是双向的（活声明必须 = 实跑值，:106-108）——但只覆盖 **8 个已知副本文件**；全仓任何其他文件新写一个活声明「140 chunks」，既不在 REPLICAS、又不是 check-counters 枚举的旧值（132），**两边都抓不到**。

**设计**：
1. **grepNum 升级为双向**：对每个口径数字族（课程内容数 / 站点 html / 课程页 / 课程卡…），在指定副本集合里扫该数字族的**全部活声明**，必须全部等于真源值（差集检测），沿革段按 HIST_ALLOW 行级豁免。验收：README 非沿革段注入「19 篇课程内容」→ 必须红。
